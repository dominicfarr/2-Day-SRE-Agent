# Chaos Toggles are decoupled from the Deploy Ledger

The fault injector needs four scenarios, but only one of them (Bad Deploy) should ever be the "right" case for a rollback; Config Drift and Downstream Dependency Outage must look temptingly deploy-adjacent without actually being deploys, or the eval would just measure "does the agent always roll back," not "does it tell the difference." We deliberately built two separate fault mechanisms: real versioned deploys recorded in the Deploy Ledger (for Bad Deploy and Noisy Decoy), and Chaos Toggles that mutate behaviour without ever touching the Deploy Ledger (for Config Drift and Downstream Dependency Outage). An agent that blames "the last deploy" for a Chaos Toggle fault is wrong by construction, which is what makes the false-rollback and missed-rollback metrics in the eval meaningful rather than circular.
